## 附 · 裁决：「能不能先把 GitHub 开源？」（2026-10-15）

> 主人问「直接先去 GitHub 上开源不行？」—— 答：**能开源，但「直接」二字是陷阱。** 分四层。

### 第 1 层：「把现在这个仓 push 上去」= ❌ 绝对不行，一 push 就是泄密

**实证**：`git ls-files lib/hub` → **24 个文件已入库**，其中含
`hub.js` · `world.js` · `god-bridge.js` · `seed-rooms.js` · `trial-pool.example.json`
—— 这些是 **Hub 服务端协议实现**，R13 红线：**永久私有**。

⇒ 直接 `git push` = 把服务端源码一次性公开，**不可逆**（可能已被 fork / mirror，删仓也来不及）。

**好消息**：密钥没进历史 —— `git log --all` 查 `*.jks` / `key.properties` / `*.p12` / `*.keystore` / `local.properties` **全部零命中**。

⇒ 唯一正确路径：`opensource_release.ps1 -RemoteUrl <url>`（18,015 B，三层闸门：排除 → 反向白名单断言 → 敏感扫描，已实跑通过）。
它产出的是**干净单提交仓**，顺带规避 git 历史里不可控的旧内容。

### 第 2 层：★ 「今天先开源 `protocol` 协议包」= ✅ 完全可行，推荐

`packages/protocol` 已就位：**12 个模块**（envelope / did / ed25519 / base58 / log / rotation / endorsement / contribution / roomRole / alias / skill / index）+ `index.d.ts` 15,614 B + MIT LICENSE + README。

| 判据 | 结论 |
|---|---|
| 依赖真机吗 | ❌ **不依赖**。真机 36 项验的是 App 端（近场 / 托办 / 互介卡 / 看板），与协议包无关；包 `npm install` 即可跑 |
| 依赖合规吗 | ❌ **不依赖**。合规（隐私政策）服务的是「收个人信息 / 服务终端用户」，开源仓库两样都不做 |
| 前置 | 只剩 **npm 开 2FA（5 分钟）** + 本轮 9 改 1 新增已提交 |
| 自检 | **172 PASS**；`verify_protocol_package.js` 断言「hub.js 导出的 28 个协议函数与包内 `===` 同一对象」 |
| 收益 | 给 `wold/1` 标准盖**时间戳** —— 正是 PRD §15「首个第三方互操作实现给永久免费 Hub 权益」的起点 |

### 第 3 层：「开源 fen 客户端主仓」= 🟡 建议等真机过一批，但门槛可降

- 开源 **≠** 发布 APK：受众是开发者，不收个人信息 ⇒ **隐私政策不是硬前置**（这点与上架不同）。
- 但真机未过 ⇒ 第一个 clone 的人跑不起来 ⇒ **开发者口碑同样不可撤回**（与 TikTok 差评同理，只是受众换成开发者）。
- ★ **门槛可降，不必等 36/36**：真机过掉 **「存量 8 项 + M1 入场 6 项」共 14 项** 即可开源；其余 22 项明确记为「该版本已知限制」并在 README 声明。

### 第 4 层：「上架」= ❌ 跳不掉

14 天封闭测试硬时钟 + AAB（当前零命中）+ 隐私政策定稿，三项都是硬门。
