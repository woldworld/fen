## 1. 缘起：外部意见说了什么

工程师的核心判断（原文要点）：

1. 新版（章回剧场）**方向值得保留**，问题在「产品看不懂、功能不够直观、视觉层次不够成熟」。
2. 四个目标：看得懂 / 看得见 / 感到专业 / 愿意行动。
3. 六阶段：① 定位与内容结构(P0) ② 视觉设计体系(P1) ③ **Agent 工作过程演示(P1·重点)** ④ 信任与隐私(P1) ⑤ 导航文案转化(P2) ⑥ 技术性能(P1–P2)。
4. 三条告诫：先改信息架构与文案再动代码；不要一次性重写整个站；用用户测试而非内部审美争论验收。

**本仓的裁决：这三点判断都成立，且第 3 条（演示）与我们「诚实边界」红线天然一致。** 但外部方案不知道本仓的硬约束（离线自足、五语种、静态生成、发布冻结），因此**不能照抄执行**，需按 §3 逐条裁决。

## 2. 现状取证（本仓实证，非印象）

### 2.1 首页 = 纯章回叙事，缺「产品表达层」

`landing/dist/index.html`（30,530 B）与 `landing/dist/zh/index.html`（26,133 B）实测：

- `h1`：**「Link every agent. Reach every real person.」**（中：「链接每一个智能体，抵达每一个真实的人。」）
- 7 个 `h2` **全是章回名**：`Entering the Wildland` / `Speaking up` / `The introduction` / `The small circle` / `Six cities` / `Wrong company` / `Coming home`（中：初入大荒 / 开口 / 引荐 / 小荒圈子 / 环游六城 / 遇人不淑 / 归巢）
- `section id`：`awaken / world / verifiable / how / local-first / cities / auditable / audit / explore`

⇒ **首页没有**：一句话产品定位段、三步工作机制、完整 Agent 交互演示、产品当前状态、开发者入口。
⇒ 工程师「用户看不懂」的诊断**在结构上成立**：用户必须先读完整部章回才能拼出产品是什么。

### 2.2 导航无 Security、无 Product、无 About

实测导航（EN）：`World / How it works / Docs / FAQ / Changelog / Cities`（6 项）
（ZH）：`大荒世界 / 怎么运作 / 文档 / 更新日志 / 常见问题 / 城市`

### 2.3 设计系统已有雏形，但**未文档化**

`landing/dist/style.css` 34,800 B，`:root` 已定义 **22 个变量**：
`--ink / --ink-soft / --ink-faint / --paper / --paper-alt / --line / --accent / --accent-strong / --accent-soft / --hero-bg-1 / --hero-bg-2 / --glow-warm / --glow-cool / --glow-teal / --grid-line / --glass-bg / --glass-border / --img-scrim / --photo-scrim / --radius / --maxw / --mono`

⇒ 工程师「建立设计系统」在本仓应理解为**补齐 + 固化成规范文档**，不是从零。缺口在：字号层级、间距栅格、组件样式、动效规则、断点表 —— 目前散落在 CSS 里，**没有单独规范文件**。

### 2.4 隐私页已相当完整，缺的是**独立 Security 页**

`landing/dist/privacy/index.html`（8,828 B）10 节：一句话摘要 / 收集什么 / AI 使用与披露 / 数据最小化（工程实证）/ 权利 / 不做的事（红线）/ 儿童 / 安全 / 国际传输 / 变更。
且已五语种：`/privacy/{en,zh-hant,ja,vi}` + 中文。

⇒ 工程师「重做信任与隐私」应**收窄为补一个 `/security/`**：讲身份如何验证、Agent 能访问什么、哪些操作须批准、签名与审计如何工作、如何撤销授权/删数据、第三方模型接触范围、**哪些已实现哪些在开发中**。隐私页偏「数据权利」，安全页偏「机制」，二者不重复。

### 2.5 演示现状：有「点蛋」与「撤回」，缺「Agent 之间怎么谈」

- 已有：`#egg` 孵化 → 起名 → 掷性格 → `#bad-line` 划掉 → `#audit-note` 浮出（0.101.0 真机截图实证，交互链全通）
- 已有：常驻 `disclaimer`（情景演绎 / 剧本化演示 / 不展示真实用户内容）
- **缺**：工程师第三阶段要求的「需求 → 我的 Agent → 找到对方 Agent → 交换允许披露的信息 → 给匹配理由 → 我审核 → 我确认 → 真人联系」全过程。

### 2.6 术语确实多套并存

实测出现的名称：`Wold`（品牌/协议）、`Fen`（客户端，`<title>Fen - …`；中文「Fen（大荒AI）」）、`World`（`/world/` 大荒世界）、`Wildland`（章回名「初入大荒」的英文）、`大荒`、`小荒`（精灵名）。

⇒ 工程师「先做术语表」成立。本仓现行可用定义（实证）：
`Wold` = 品牌与协议名（协议 `wold/1`，协议 CC-BY-4.0）｜`Fen` = 个人 AI 客户端（APK `applicationId = world.wold.fen`）｜`World` = 大荒世界（房间/分身社交）｜`大荒` = Wold 中文名｜`小荒` = 章回剧场精灵形象名（非产品名）。
**待核**：App 内 ARB 首屏文案是否与官网同源（不同源的话，改标语要两边一起动）。

### 2.7 ★ 发布通道：改了也看不见（本仓独有，外部方案不知）

2026-10-13 实测 `www.wold.world`：首页 **12,327 B**（本地 30,530 B）；`egg/sprite-name/dice/hatch` **全 0**；sitemap 32 条、**无 `/download/`**、旧六城；**`/changelog/` 最高版本 = `0.95.0`**（本地 0.101.0）；`Server: cloudflare`。
另：`deploy/setup-caddy.ps1` 生成的 Caddyfile **只有 `reverse_proxy`（hub→3000 / world→3100），零 `file_server`** ⇒ 官网被拷到 `C:\dahuang-site\` 却**没有对外入口**。

⇒ **阶段 F 是其他一切阶段的价值前提。**

## 3. 外部方案 × 本仓红线 —— 逐条裁决

### 3.1 可直接采纳（无冲突）

| 外部建议 | 本仓落地形态 |
|---|---|
| 首页重排为：定位 → 三步 → 场景 → 演示 → 信任 → 状态 → 开发者 | 新增「产品表达层」区块，**章回保留为独立体验页**（`/story/` 或首页后半段，不删） |
| 做 Agent 交互全过程演示 | 新 `landing/data/demo.json`（zh/en）+ 前端分步交互，**必须带「交互演示/模拟数据」标注**（承 R27 与既有 `disclaimer` 判据） |
| 首屏 = 定位 + 核心机制 + 明确下一步 | 首屏加一句话定位 + 三步机制图（内联 SVG）+ 单一主 CTA |
| 移动端 / 图片 / 死链 / 无障碍 / 性能 | 纳入阶段 E，用实测数据，不预重写框架 |
| 主 CTA 只留一个 | 承 ADR-001：主 CTA = 官网自托管 `/download/` 下载 APK；次 CTA = 阅读协议/文档 |

### 3.2 必须改造后采纳（有连带成本，需主人拍板）

| 外部建议 | 连带影响 | 裁决 |
|---|---|---|
| 改主标题为「Your AI. Your network. Real connections.」 | 五语种 `site.json`/`site-zh.json` + `<title>`/`og:` + sitemap + **App 内 ARB 首屏是否同源（待核）** + 既有守卫可能对标语有判据 | **列为候选，不直接改**。先做术语表与定位，标语最后定；改则五语种同批 |
| 导航改 `Product / How It Works / Security / Developers / About` | 现有 6 项导航 + 五语种 + 34 条 sitemap + `/world/ /docs/ /faq/ /changelog/` 真实页面 | **不照抄英文导航**。按「本仓真实存在的页面」重排：世界 / 怎么运作 / 安全 / 文档 / 更新日志 / 常见问题 / 城市。**不为导航完整而建空页**（承外部方案自身告诫） |
| 「找 5–10 位不了解项目的人测试」 | 本仓无用户池 | 见 §5 替代验收体系，**禁止**凭空报「理解率 X%」 |

### 3.3 不能直接做（红线冲突）

- **外部 CDN / 字体 / 组件库 / 3D 引擎 / 粒子背景**：违反离线自足判据（视觉层只允许内联 SVG + 本地相对路径资源）。演示动画一律内联 SVG + CSS/原生 JS。
- **埋点 / 访问分析脚本 / 错误监控 SaaS**：会引入外部 `http(s)://` 请求，**与离线自足判据冲突**。如确需，必须主人特批并改判据。
- **把规划中功能写成已实现**：违反 R27「对外主张必须可证实」+ 本仓「诚实边界」。`status` 区块只写真实可用能力。
- **黑底蓝紫渐变 + 发光卡片**：外部方案自己也不建议；且本仓明暗双主题靠 CSS 变量，硬改会破坏「明暗免费」。
- **一次性重写整个站**：违反本仓「按 MINOR 版本增量交付」纪律。

### 3.4 阶段顺序调整（相对外部方案）

外部方案把「视觉设计(P1)」排在第二。本仓**把「术语 + 信息架构 + 文案」提到最前**，理由：**文案定不下来就改样式，必然返工**（这也是外部方案的告诫一）。

## 4. 实施计划

### 阶段 F（P0·前置）打通发布通道 —— 否则后面全白做

| 项 | 内容 |
|---|---|
| 改 | `deploy/setup-caddy.ps1` 生成的 Caddyfile 补 `root * C:\dahuang-site` + `file_server`；使用说明补「官网 = 主域名」 |
| 收口 | `deploy/Caddyfile.example` 与脚本**必须同源**（现状两者不一致：样例有 file_server、脚本没有） |
| 验收 | ① 脚本与样例差异断言（新增守卫）；② 本地起静态服务，`/` 返回含 `egg` 的 HTML；③ 重打部署包并核对包内 `site/index.html` CRC |
| 另需拍板 | 是否**解除发布冻结**把 0.96→0.101 的官网正式发到 `wold.world` |

### 阶段 A（P0）术语表与产品定位

1. 落一份 `landing/data/glossary.json`（+ zh），**机器可读**，供全站文案引用。
   字段建议：`term / zh / en / 定义 / 是不是产品名 / 首页是否突出`。
   现行定义见 §2.6（已实证）；**「首页是否突出」默认 `false`**，只有 `Wold`、`Fen`、`World` 为 `true`。
2. 定一句话定位（候选，待主人选定）：
   - EN：`Fen is your personal agent in the World — it meets other people's agents first, and only calls you in when a real connection is worth your time.`
   - ZH：`分身 Fen 替你先去认识别人的分身；值得再由真人出面。`
   - **标语（h1）变更留到阶段 B 末，不先改。**
3. 验收：新增守卫断言「首页不出现 glossary 标记为 `false` 的术语」（正控：注入一个 `false` 术语必须翻红）。

### 阶段 B（P0）首页信息架构与文案

在章回**之前**插入「产品表达层」，顺序按外部建议：
`一句话定位 + 主 CTA` → `三步工作机制` → `实际价值场景` → `Agent 演示入口` → `信任摘要` → `当前状态` → `开发者入口` → `（章回剧场，作为独立深度体验）`

- 三步机制图：**内联 SVG**（离线自足），不用 GIF/视频。
- `当前状态` 区块：只写真实可用能力；预览/开发中项**显式标注**。
- 文案改 `landing/data/site.json` + `site-zh.json`，**五语种同批**。
- 验收：① 守卫断言首页前 N 屏含「定位 / 三步 / 演示 / 状态」四类区块；② 真机截图目视（明暗 × 中英四组合）；③ **章回区块仍在**（防止改架构把剧场删掉）。

### 阶段 C（P1）设计系统规范化

- 新增 `landing/DESIGN.md`（规范文档），把已有 22 个变量扩成完整 token 表：色板 / 字号层级 / 间距栅格 / 圆角 / 动效时长 / 断点 / 组件样式（按钮·卡片·标签·表单·导航）。
- 落地顺序：**首页高保真 → 抽出组件 → 应用到其他页**（不一次性全站重画）。
- 验收：CSS 变量新增项有对应规范条目（守卫可断言「规范里列到的变量在 style.css 里都存在」）；明暗双主题四组合截图目视。

### 阶段 D（P1·重点）Agent 交互全过程演示

场景按外部建议（跨境电商 / 澳大利亚市场）**改造为本仓真实语义**：

1. 我提出需求 → 2. 我的 Agent 提取条件 → 3. 候选 Agent 及能力 → 4. 交换**允许披露**的信息 → 5. 匹配理由 → 6. **我审核将要披露的内容** → 7. 我确认 → 8. 才进入真人联系。

- 数据：`landing/data/demo.json`（zh/en），**标注 `simulated: true`**。
- **必须显式标注「交互演示 / 模拟数据」**（承 R27 + 既有 `disclaimer` 判据 + 外部方案告诫）。
- 每步显示「实际发生了什么」和「我能控制什么」两栏 —— 这是外部方案要求的，也是本仓「能力边界诚实」的一贯做法。
- 验收：① 守卫断言演示区含 `simulated` 标注（正控：去掉标注必须翻红）；② 演示区**不写 DB / 不发网络请求**（源码断言）；③ 五语种文案齐；④ 真机走完 8 步截图目视。

### 阶段 E（P1/P2）Security 页 + 导航/CTA + 性能

- 新增 `/security/`（五语种）：身份验证 / 数据访问范围 / 自主操作 vs 须批准 / 签名与审计 / 撤销授权与删数据 / 第三方模型接触范围 / **已实现 vs 开发中**（诚实分栏）。
- 导航按「真实存在的页面」重排，加入 Security；**不建空页**。
- CTA 统一：主 = 下载 APK（`/download/`），次 = 文档/演示。
- 性能与无障碍：移动端布局、图片压缩与加载、动效卡顿、横向溢出、死链、焦点与对比度、`alt` 与 OG 信息 —— **先测量再改**，不预重写。
- 验收：死链扫描（承既有外链判据）+ 移动端 390px 截图 + 明暗四组合目视。

## 5. 验收体系（可执行，替代「5–10 位用户测试」）

| 层 | 判据 | 谁来做 |
|---|---|---|
| **结构守卫**（新增） | 首页必须含「定位/三步/演示/状态」四类区块；演示含 `simulated` 标注；首页不得出现 glossary 标 `false` 的术语；`/security/` 与导航同源 | 自动化，进 `run_all_verify_node.js` |
| **反半接线** | 每个区块在 **zh 与 en 两侧**都必须有真实内容（承 R27「多语言站同构是整站要求」） | 自动化 |
| **真机目视** | 明/暗 × 中/英 **四组合**，各截首屏 + 交互后；逐张目视 | 人工 |
| **可理解性代理测试** | 把首屏截图交给**未参与开发的人**（主人或第三方），只问一句「这是什么、我为什么要加入」；**记录原话，不报百分比** | 人工 |
| **诚实边界断言** | 「当前状态」区块的任何能力描述必须能在代码/文档里找到实现证据；演示必带模拟标注 | 自动化 + 人工 |

★ **禁止**：用「用户理解率 X%」「N 人测试通过」这类无法复现的数字做验收结论。没有真实用户池就是没有，如实写。

## 7. 版本与收口约定

- 每个阶段 = **一个 MINOR 版本**（例：0.102.0 = 阶段 F；0.103.0 = 阶段 A+B；0.104.0 = 阶段 D……），**DB 不动**。
- 每阶段必走：四关回归（`flutter analyze lib tool test` / `flutter test` / `dart run_all_verify` / `node run_all_verify_node`）→ 三件套（CHANGELOG `[x.y.z]` CRLF + 交付记录新 § LF + PRD 四落点 LF）→ pubspec bump → 受控提交（EXPECT↔staged 双向比对 + 密钥扫描）。
- **landing-only 改动**：仍 bump + 全量回归，但**不重出 APK**；**部署包必须重打**（site 同步）。
- 改 `pubspec`/`CHANGELOG` 会连带 `make_download_page.js` → `landing/build.js` → node 全量 → 部署包重打（承 0.100.0 实证的连带链）。

## 8. 诚实边界与风险

- **改了官网 ≠ 用户看得到**：阶段 F 不完成，阶段 A–E 的成果只存在于本地与部署包里。
- **术语表不能凭空编**：以 §2.6 实证为起点，凡本仓没有权威定义的，标「待主人裁定」，不猜。
- **标语变更有连带成本**（五语种 + App ARB 同源待核 + 守卫），列为候选而非必做。
- **演示再好也是演示**：外部方案明确要求标注；本仓红线更严 —— 宁可少说，不可说成已上线能力。
- **无真实用户池**：可理解性只能做代理测试并如实记录，**不编造人数与百分比**。
- 外部方案建议的「四周上线」**不采纳为承诺**：本仓按版本迭代节奏推进，周期取决于主人拍板与验收，不为赶时间牺牲质量（这也是外部方案自己的告诫）。
