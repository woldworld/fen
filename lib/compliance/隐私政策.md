## 1. 一句话摘要

| 问题 | 回答 |
|---|---|
| 你们把什么放在**我们服务器**上？ | **极少**：一个身份公钥、一个不记名的昵称/面具、以及公开的**只追加日志里的哈希**（不含原文）。运行时我们还会看到你的**来源 IP** —— 仅用于限流与滥用防护，**只在内存里、不进数据库**（见 §2）。 |
| 私钥在你们手上吗？ | **不在。** 私钥**从不出设备**——客户端 UI 里没有"手填签名"入口，服务端也没有任何接收私钥的接口。 |
| 你们的日志里能看到我聊了什么吗？ | **不能。** 透明日志只保存**叶子哈希**（不可逆摘要），不保存对话原文。 |
| 我能导出 / 删除吗？ | **能。** 本地数据可**加密导出**为一个归档文件、可删除；服务器侧身份数据可申请删除（见 §5）。 |

## 2. 我们收集什么、为什么、存在哪

| 数据 | 用途 | 存放位置 | 是否可删除 |
|---|---|---|---|
| **身份公钥**（Ed25519，不含私钥） | 让其他人能验证"这条记录确实是你签的" | 服务器（Hub） | 可（注销时删除/吊销） |
| **昵称 / 面具（mask profile）** | 显示名；**不要求真实身份** | 服务器 | 可 |
| **透明日志叶子哈希** | §16 可验证性：让任何人能监督日志未被篡改 | 服务器（**公开可下载**） | 不可（只追加是它的全部意义；但其中**不含原文**） |
| **技能上架清单**（作者自愿公开） | 技能市场的署名与定价 | 服务器 | 可下架（保留历史以供验签） |
| **端到端加密的消息** | 用户间通信 | 服务器仅存**密文**，密钥在设备 | 可删除 |
| **模型调用计量**（token 数、费用） | 计费（体验额度/作者分成） | 服务器 | 随账本保留 |
| **来源 IP** | 限流与滥用防护：按 IP 计每分钟请求量、按 IP 配给体验额度 | **仅内存**的限流计数表；运行日志里只写**截断网段**（如 `1.2.3.0/24`），不写完整 IP | 随进程重启清空；计数在窗口过期后由定时清扫删除（见下） |

**来源 IP 的保留期（写成数字，不写"短期"）**：

| 形态 | 保留多久 | 谁清掉它 |
|---|---|---|
| 分钟级限流计数（每分钟请求量、体验额度每分钟配给） | **最长 2 小时**：窗口 60 秒，清扫每 10 分钟一次，超过 2 个窗口没有任何访问即删除 | 进程内定时清扫；重启进程立即清空 |
| 按日体验额度计数 | **最长 25 小时**：跨日后的下一次清扫删除 | 同上 |
| 运行日志里的来源网段 | 本软件**只写进程标准输出、不落盘**；若部署方重定向到文件，保留期由**该部署方**决定 | 部署方 |

★ 完整 IP **不写入任何持久化文件**：它只在内存里充当计数键。
★ 来源 IP **不用于用户画像、不与你的身份写入同一条记录、不用于广告**。

**我们不收集**：通讯录、精确位置、设备唯一广告标识、真实姓名/身份证件、支付卡号（**我们不经手你的卡号**：即便开通付费，支付也由持牌支付机构处理；资金流向见服务条款 §4）。

**透明日志的保留期（写成数字，不写「长期」）**：

| 形态 | 保留多久 | 谁清掉它 |
|---|---|---|
| **叶子哈希**（§16 可验证性） | **永久**：只追加、不可删 —— 这是可验证性的代价 | 无删除路径（代码侧亦无） |
| **公开可下载的日志文件本身** | 官方 Hub 当前**不轮转、不删除**；自建 Hub 由该部署方决定 | 部署方 |

★ 叶子哈希**永久保留**是可验证性的代价，不是疏漏：一旦允许删除，任何人就无法再独立复算「日志未被篡改」。
★ 其中**不含原文**（只有单向摘要），所以被永久保留的不是你的消息内容。

### 2.1 自建 Hub（自托管）：谁是你数据的控制者

Fen 客户端可以连接**你自己或第三方搭建的 Hub**。此时请明确：

- **该 Hub 的运营者（不是我们）是其数据的控制者**：它上面存什么、留多久、向谁开放，由它的运营者决定并负责。
- **我们不接触**自建 Hub 上的任何数据，也**无法**代你删除或导出其中的内容 —— 请直接联系该服务器运营者行使你的权利。
- ⇒ 因此 §2 表格描述的收集范围**仅适用于官方运营的 Hub**；§5 列出的权利，在自建 Hub 上亦应向该运营者主张。

## 3. AI 使用与披露

- 平台上的**智能体 / 分身可能由 AI 驱动**。按 PRD §9.2，我们采取**产品级明示 + 首次自报身份**：与 AI 的第一轮交互即声明其为 AI，该声明**默认开启且不可关闭**。
- 若你使用"试用额度"（由平台代调模型），调用为你发起、结果返回给你；我们保留交互日志以备披露义务举证，但**不做画像、不做广告用途**。
- **试用期额度有限（默认 20 轮）且仅用于体验**：期间你的对话内容会经我们的服务器转发至模型服务提供商处理，链路按**你发起请求时的来源地区**选择（以服务器记录的来源国家／地区为准）。额度用尽后，填入你自己的模型密钥即可继续——此后调用**不经过我们**，也不经过试用转发链路。

| 你发起请求时的来源地区 | 转发至 | 对话内容流向 |
|---|---|---|
| 中国境内 | 中国境内的模型服务提供商（如阿里云百炼 / 火山引擎） | **不离开中国境内** |
| 中国境外 | OpenRouter, Inc.（美国） | **不进入中国境内** |

按来源地区选择链路，是为了让两条链路各自落在它应当适用的法域内 —— 这与「按地区屏蔽访问」不是同一件事。**当前我们不会因为你所在的地区拒绝你访问，但我们保留在法律要求时限制特定地区访问的权利。**
- 若你在客户端自带模型密钥，则调用**不经过我们**，我们无从得知内容。

## 5. 你的权利（访问 / 导出 / 更正 / 删除）

| 权利 | 怎么行使 |
|---|---|
| **访问 / 导出** | 客户端"导出本地数据"，导出一个**口令加密**的归档文件（`.dahuang`）。 |
| **更正** | 昵称 / 面具可在设置中随时修改。 |
| **删除** | ① 本地数据：一键清除；② 服务器身份数据：见下。 |
| **撤回同意 / 注销** | 提交注销申请至 privacy@wold.world。 |

**关于导出（说清它到底是什么）**：

- 归档以**你设置的口令**加密（与恢复码同一套加密），**我们无法解开、也不会经手**。
  请把它存在**你自己**认为安全的地方。
- 归档包含**你的本地数据**（身份记录、社交图谱、互介记录、透明日志锚点等），
  但 ★ **不包含你的私钥** —— 私钥的备份是另一件事（见《服务条款》§2.1「备份身份」），两者**分开保管**。
- ⚠️ **导出的是文件，不是"同步"**：我们不提供云端同步。导出之后文件放在哪、能不能找回来，
  由你自己决定。
- 透明日志带**接续锚点**：把归档导入另一台设备时，若两边的日志对不上，客户端会**拒绝导入**
  并告知原因（这是"日志不可被悄悄改写"的另一面）。

**关于删除的诚实说明**：透明日志中的**哈希**不可删除——这是"可验证性"的必要代价，即任何人都能验证历史未被改写。但请注意：

> **日志里的哈希是单向摘要，且不含任何原文。** 删除你的身份映射后，那段哈希不再能关联到"你"。

我们承诺：注销请求在 **30 日内**处理完毕（法律另有要求除外）。

## 6. 我们**不做**的事（红线）

| 不做 | 原因 |
|---|---|
| 用户间资金流转 / 平台内提现 | PRD §9.1：**永不出金**，只做平台内单向消费；需要时用持牌方，优先海外 |
| 发行股权 / 利润分红 | 多法域下可能构成证券发行；且与"不必交出身份"的核心价值冲突 |
| 出售 / 共享你的个人数据给第三方广告商 | 与本地优先原则直接冲突 |
| 要求实名才能使用核心功能 | 匿名是产品的基础价值，不是可选项 |

## 8. 安全

- 传输全程 TLS；身份签名使用 Ed25519。
- 服务端**不持有**用户私钥，因此即使服务器被入侵，也无法冒充任何用户签名。
- 数据泄露事件：我们将在确认后 **72 小时内**通过 privacy@wold.world / 站内公告通知受影响用户与监管机构（按适用法律）。

### 8.1 通知与推送：数据怎么流动

**当前版本：通知在本机生成，不经任何服务器。**

- 客户端展示的通知（委托到达、会客厅有人 @你、分身起草了待批准的建议卡等）**全部在你的设备上本地生成并显示**，由 App 内部事件总线（`AppEvents`）触发，**不经过我们的服务器，也不经过任何第三方推送通道**。
- 实证位置：`lib/core/notification_service.dart`（全文无 http / 网络调用）；后台值班心跳运行在独立 isolate 中，会在该 isolate 内重装同一套旁听器，目的只是让后台事件也能被看见，**同样不发起任何网络请求**。
- 该服务**不申请**精确闹钟权限（`SCHEDULE_EXACT_ALARM`）；通知渠道名称在首次创建时按系统语言固化一次。

⚠️ **已知边界**：后台 isolate 中"通知是否真的弹出来"**仍属真机未验**（本环境无设备，无法自动验证渲染结果）。

**若未来引入远程推送，我们承诺上线前先做到三件事**：

1. **默认走系统级推送通道**（Google / Apple），**推送载荷不含消息内容**；
2. 为自建 Hub 用户提供**可选的自建推送方案**；
3. 在《隐私政策》中**逐条写明数据流经方**（谁发、谁转、谁收、含哪些字段、保留多久）。

> ★ 原因：推送链路一旦经过我们的服务器，就会重新建立"运营者 ↔ 用户"的数据连接，
> 从而**破坏 §2.1 与《服务条款》§2.5 所声明的责任切割**。这是设计决策，不是措辞偏好。
