## 2. 该错的地方（3 处，都是硬伤）

### 2.1 ★★ 加密出口管制文档「密码库清单」写错，且漏列两个包

**文档原话**（`lib/compliance/加密出口管制.md:35-39`）：

> **依赖来源**：`cryptography: ^2.9.0`、`crypto: ^3.0.3`（`pubspec.yaml:34`–`35`）。
> ★ …算法实现全部来自第三方开源包 `cryptography`，本项目**没有**自研任何密码算法…

**磁盘事实**：

- `lib/core/session_crypto.dart:7` → `import 'package:encrypt/encrypt.dart';`
- `:214` / `:227` → `Encrypter(AES(key, mode: AESMode.gcm))` —— 这是 **`encrypt` 包的 API**，不是 `cryptography` 的
- 因此 AES-256-GCM（**业务消息加密，最核心的那一环**）实际由 `encrypt 5.0.3` 实现，其底层是 `pointycastle 3.9.1`（`pubspec.lock` 实证）
- ⇒ 文档说「全部来自 `cryptography`」**是错的**；漏列 `encrypt` 与传递依赖 `pointycastle`（还有 `asn1lib 1.6.5`）

**为什么这条算硬伤**：这份文档的全部价值就是「给律师一份**完整**的密码物项清单」。清单漏了实际执行 AES 的那个库，等于律师拿着不完整的输入做 EAR / de minimis 判断。而且 `pointycastle` 是 Bouncy Castle 血统的 Dart 移植 —— 「用了哪些密码库、来自哪」正是出口管制要问的第一件事。

**修法**：§1 依赖行改为四个包 + 各自版本与用途；删掉「全部来自 `cryptography`」这句话，改成「AES-GCM 走 `encrypt`（PointyCastle），X25519/HKDF/Ed25519/AesGcm 走 `cryptography`」，并在 §6 待裁决项里补一问「第三方密码库的来源地是否影响 de minimis 计算」。

### 2.2 ★★ IP 被处理但隐私政策一个字没提

**代码事实**（`lib/hub/hub.js`）：

| 行为 | 位置 |
|---|---|
| 每个请求把来源 IP 打进运行日志 | `:708` `console.log(… ' from ' + req.socket.remoteAddress)`（裸 remoteAddress，无任何截断） |
| 匿名读按 IP 限流 | `:455` `anonHits`、`:457` `clientIp` |
| 体验额度按 IP 双重配给（每分钟 + 每天） | `:172` `trialIpHits`、`:173` `trialIpDay`、`:192` `trialIpDaily` |

**隐私政策事实**：`隐私政策.md` §2 数据表共 6 行（公钥 / 昵称 / 叶子哈希 / 技能清单 / 密文消息 / 计量），**没有 IP**；「我们不收集」那一行列的是通讯录、精确位置、广告标识、姓名证件、卡号 —— **也没有 IP**。

**判断**：IP 在 GDPR 与中国《个人信息保护法》下都是个人信息。现在的状态是「**代码在处理、政策里查不到**」。计划书 §2.2 恰好写着「IP 等元数据短期保留，**保留策略公开透明**」，§5.2① 又要求「公开日志保留策略」—— 这一条我们**正好没做**，而代码里已经在做。

**修法（顺序不能反）**：
1. 先定行为：`console.log` 的 IP 改脱敏（如只留 `/24` 段或哈希前 8 位），或明确「不打 IP」；
2. 再写政策：§2 增一行「IP（限流与滥用防护）→ 内存/运行日志 → 保留 N 天 → 不用于画像」；
3. 五语种同步，重打包（政策进 `dist`）。

### 2.3 ★ 限流表只增不删 —— 既是内存泄漏，也是「保留期」名不副实

**代码事实**：`countWindow`（`hub.js:433`）只重置计数、**从不 `delete`**；`trialIpDaily`（`:192`）只按日重置 `count`、**键永不删**；`reportRateOk`（`:43`）同样只重置。全项目 `anonHits.delete` / `trialIpDay.delete` / `trialIpHits.delete` / `prune` / `clear()` **命中数均为 0**。

**现存 5 张只增表**：`hits`（按身份，60 秒窗）、`anonHits`（按 IP，60 秒窗）、`trialIpHits`（按 IP，60 秒窗）、`trialIpDay`（按 IP，按日）、`reportHits`（按身份，1 小时窗）。

> ★ **订正（2026-10-20 实施清扫时发现）**：本报告初稿把 `byAgent`（`:927`）也算作只增表，**这是错的**。
> 那是换钥链端点里 `const byAgent = new Map()` 的**请求内局部变量**，随请求结束被回收，不跨请求、不累积。
> 判据：它在全文件**没有任何模块级声明**，只在该 handler 作用域内出现。
> —— 留着错判会让下一个人去"修"一个根本不漏的 Map，同时**漏掉真正要治的那五张**。

**后果两条**：
- **工程**：进程不重启，见过的每个 IP / agent 永久占内存 ⇒ 长期运行的单人 Hub 会缓慢上涨（计划书 §5.4 讲「服务器安全事件」，这条属于同一栏）；
- **合规**：政策一旦按 §2.2 写出「短期保留」，实现却是「进程生命周期内无限保留」，就又造出一句**新的假承诺**。

**修法**：给这些 Map 加一个定期清扫（如每 10 分钟清掉 `windowStart` 早于 2× 窗口的项、`trialIpDay` 清掉非今日的键），并把清扫周期写进政策的保留期数字。

### 2.4 新发现（本轮实施时顺带查出，**未修**）：隐私政策 §5 的表格被一段无序列表截断

`隐私政策.md` §5 的权利表只写了 3 行（访问/导出、更正、删除），第 4 行
`| **撤回同意 / 注销** | 提交注销申请至 privacy@wold.world。 |` 被挤到**一整段无序列表之后**（原 `:96`）。
后果：那一行**不再属于表格**，渲染成一段带竖线的普通文字 —— 也就是「注销」这项权利的表格形态丢了。

- 为什么本轮不动它：它是五语种同构的结构问题，属于 0.115.0 之前就存在的排版欠账，与本轮三件 P0 无因果关系；
  一次改五份文件会扩大改动面，且需要重新目视五个语种的表格渲染。
- 已登记为待办（《待填清单》/ PRD 未决缺口），下一轮与其它法务文本改动同批修。
- ★ 判据（下次修时照这个验）：五个语种的 §5 都要让「撤回同意/注销」行**紧跟在前 3 行之后、中间无列表**。

## 4. 需要你拍板的一处（方向性冲突，不是漏做）

**两条都写进了对外文件，逻辑上互斥：**

| 出处 | 原话 |
|---|---|
| 计划书 §5.1 表3 / §5.2⑥ / §8-D2 | 「运营者为境内个人」⇒ **屏蔽中国大陆访问与注册**，「实测不可从境内注册使用」 |
| 我们 `隐私政策` §3 × **五语种** | 「按来源地区选择链路…**我们不因你所在的地区拒绝任何人访问**」；且官网 `selfhost.json` 在推「Mainland cloud, through our link」 |

**这不是执行不到位，是我们做了一个和计划书相反的产品决策**（境内也服务，且境内请求走境内模型商）。这个决定本身可能是对的 —— 但它把计划书里那条「屏蔽境内」的红线**变成了另一套义务**：

- 若坚持「境内可访问」⇒ 需要的是**境内经营合规**（ICP 备案、算法备案、生成式 AI 服务备案、境内主体与收汇），计划书 §5.1 那条「屏蔽以避免被认定面向境内经营」就整条作废，得改计划书；
- 若要回到计划书 ⇒ 就得删掉隐私政策那句五语种承诺、关掉境内链路与境内云推荐，且**已发出去的 APK 里那句话收不回来**（只能下一版改）。

**★ 2026-10-20 晚已拍板（补记，非计划）**：主人选 **「删强承诺、改中性措辞」** —— 不动地区政策、不做屏蔽，但把五语种那句「不因你所在的地区拒绝任何人访问」删掉，改成「当前我们不会因为你所在的地区拒绝你访问，但我们保留在法律要求时限制特定地区访问的权利」。理由：① 那句强承诺**从未被任何线上行为兑现**（`hub.wold.world/health` 实测 `agents:0, messages:0`，试用代调默认全关）；② 真做境内合规与产品红线**结构性冲突**（可追溯/留存/实名 vs 不存原文/不落完整 IP/端到端加密），且需境内主体，个人办不了；③ 真屏蔽境内会自伤（运营者本人与国内测试都在境内）。★ 已同步：门禁新增**第 28 条**（境内经营合规重估，触发式：境内月活 > 100 / 开始收费 / Hub 迁境内 / 出现境内主体合作方 —— 任一触发即按 B 档重估）；`tool/verify_landing.js` 的旧强承诺断言改为「**必须消失**」的反断言 + 新中性句正断言 + 毒注入正控。

**我不能替你选。**（本段保留，作为决策过程的记录。）但按门禁 B 档规则：**B 档是「对外宣称门禁」—— 一旦声称就必须绿，否则删掉那句宣称。** 现在这句宣称对应的合规义务（境内经营）我们没有一项在做，按规则它现在就该被处理。
